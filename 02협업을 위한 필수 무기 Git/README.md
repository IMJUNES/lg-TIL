# 협업을 위한 필수 무기 Git

2026.10.19

## 1. 배운 내용

1. Git은 소스코드의 변경 이력을 관리하고 필요할 때 이전 버전으로 되돌릴 수 있는 분산 버전 관리 시스템
(SourceTree는 git의 브랜치가 나뉘고 합쳐지는 상태를 시각적으로 편리하게 확인 가능)

`git add`로 변경한 파일을 담는다
`git commit`으로 작업 내용을 커밋할 수 있다. 
`git reset 해시값`은 이전 커밋으로 돌아갈 때 사용하고 
`git revert`는 특정 커밋에서 변경한 내용을 취소할 때 사용한다.

브랜치는 하나의 프로젝트에서 여러 작업을 독립적으로 진행하기 위한 방법이다. 강의에서는 브랜치를 서로 다른 공간에 비유했고 
`git switch`로 현재 브랜치를 변경할 수 있다(공간이동이라고 표현)
현재 선택되어 있는 브랜치는 삭제할 수 없어서 다른 브랜치로 이동한 후 삭제해야 한다.

서로 다른 브랜치를 합치는 방법에는 `merge`와 `rebase`가 있다. 
`git merge`는 작업 기록을 유지하면서 합치는 방법이고 
`git rebase`는 한 브랜치의 작업을 다른 브랜치 뒤에 이어붙여 기록을 정리하는 방법이다.

2. GitHub는 git으로 관리하는 프로젝트를 원격 저장소에 올려 다른 사람들과 공유하고 협업할 수 있는 온라인 플랫폼이다.

vscode와 연동 후
`push`로 내 컴퓨터의 작업 기록을 GitHub에 올리고 
`pull`로 GitHub의 변경 내용을 가져올 수 있다. 
`git clone`으로 다른 사람의 프로젝트를 내 폴더로 가져올 수도 있다.

## 2. 실습

Vs code와 git bash 및 Source Tree를 이용해 Yaml 파일을 만들고 git으로 관리해 보았다.

강의 동영상에서는 `git commit -m "first commit"`이라고 입력했지만 한글도 사용할 수 있는지 궁금해서 `git commit -m "첫 커밋"`으로 기록해 보았다. 한글로도 커밋 메시지를 작성할 수 있었다.

초반에는 `git add .`로 파일을 추가한 뒤 `git commit -m`으로 기록했다. 실습 중반부터는 기존에 Git에 등록된 파일을 수정할 때 `git commit -am`으로 두 과정을 한 번에 처리해 보았다. 
새로 만든 파일은 먼저 `git add`를 해야 한다는 점도 배웠다.


이후 `reset`과 `revert`로 작업 내용을 되돌리는 방법을 살펴보고 브랜치를 만들어 이동하며 파일을 수정해 보았다. `merge`와 `rebase`로 브랜치를 합치고 충돌을 해결하는 실습도 진행했다. SourceTree에서는 브랜치가 나뉘고 합쳐지는 모습을 확인할 수 있었다.

git 실습을 마친 후에는 Github에 폴더를 올리고 `push`와 `pull`을 사용해 보았다.

**VS Code와 GitHub에서 각각 수정한 내용 합치기**

VS Code에서 파일을 수정하고 GitHub 사이트에서도 같은 프로젝트의 파일을 직접 수정해 보았다. 양쪽에 서로 다른 작업 기록이 생기면 바로 `git push`를 했을 때 업로드가 거절될 수 있다는 걸 알게 되었다.

이때 `git pull --no-rebase`로 GitHub의 변경 내용을 가져와 내 작업과 합친 뒤 `git push`로 다시 올리는 방법을 배웠다. 같은 부분을 다르게 수정했을 때는 충돌을 직접 해결해야 한다.


## 3. 트러블슈팅 및 궁금했던 점

**1. vscode yaml 파일 아이콘이 강의 동영상과 차이가 있었따.**

강의 동영상에서는 YAML 파일이 빨간색 아이콘으로 표시되는데 내 VS Code에서는 보라색 `!` 아이콘으로 표시되었다. 파일에 문제가 있는 것은 아니었고 VS Code의 파일 아이콘 테마가 다르기 때문이라는걸 인터넷 검색을 통해 알게 되었다.

**2. 처음 SourceTree에서 프로젝트 폴더를 열 때 오류가 발생했다.**

`fatal: this operation must be run in a work tree` 오류가 발생했다. `.git` 폴더를 직접 선택한 것이 원인으로 보였고 실제 프로젝트 폴더를 선택해야 한다는 것을 알게 되었다.

## 4. 느낀점

Git과 Github를 사용하면 소스코드의 변경 이력을 관리할 수 있고 문제가 발생했을 때 이전 버전으로 되돌릴 수 있다는 점이 유용하다고 느꼈다.

또한 팀원별로 브랜치를 생성해 각자 독립적으로 작업하고 나중에 작업한 내용을 하나의 브랜치로 합칠 수 있겠다는 생각도 들었다.
